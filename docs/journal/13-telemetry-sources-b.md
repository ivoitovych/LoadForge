# Stream 13 — Telemetry sources: power, performance counters, EDAC

**Written:** 2026-10-20 16:27 UTC
**Branch:** `feature/telemetry-sources-b`

## Established by experiment

All on the development VM: `Linux vm 6.18.44-fc-v139 #1 SMP PREEMPT_DYNAMIC x86_64`, 4 vCPUs, root.

- **No hardware counter is available in this VM.** `perf_event_open` of cycles, instructions, cache misses and branch misses (`PERF_TYPE_HARDWARE`, user space only, pid 0) fails with `ENOENT`; a software event (context switches) is granted. `perf_event_paranoid` is **0** here, not the 2 PLAN F3 measured in its container: the number is a property of the machine, which is why the source reads it and names it.
- **The power PMU exists and has only `energy-psys`.** `/sys/bus/event_source/devices/power` is type 9, `cpumask` 0, event `energy-psys` = `event=0x05`, scale `2.3283064365386962890625e-10` (exactly 2^-32 J), unit `Joules`. There is no `energy-pkg`. That tree is committed as `tests/fixtures/sysfs/powercap/perf-psys-only`, the one real capture of a power interface; with it the source reports package power as unsupported.
- **The power PMU refuses the bits a process counter takes.** `perf_event_open(type 9, config 5, pid -1, cpu 0)` with `exclude_hv=1` and `inherit=1` is `EINVAL`; with neither it succeeds, and after RESET and ENABLE a read returns 24 bytes (value, time enabled, time running; value 0 here). So `PerfEventSpec` carries `user_only` and `inherit` as choices, and the power source sets neither.
- **`/sys/class/powercap` and `/sys/devices/system/edac` are absent.** No powercap and no EDAC fixture could be captured; see Open.
- **`perf_event_open` success depends on the runner.** A runner's PMU, paranoid level and seccomp profile decide it, so `RealSyscalls::open_perf_event` and `control_perf_event` take no branch of their own (`result_or_error`), and the real-kernel tests assert what holds either way.
- **The test fake needed paths.** `FakeSyscalls` served one file; a source that reads a directory needed a tree (`add_file`, `deny_file`, `fail_file_read`, `remove_file`, `add_tree`). Denial is the fake's refusal of the open over the committed files, because CI is root and no mode refuses root.
- **Coverage traps met again.** (1) §1.13: an aggregate such as `MetricStatus{make_metric(..), Unavailable{..}}`, or `std::get<Unavailable>(out.emplace_back(..))` (a `bad_variant_access` arm), leaves branches nobody can take; failures are now filled in place a field at a time, and a local `Unavailable` is emplaced once. A `continue` after such a local leaves its cleanup on a line of its own, so the arms use if/else. (2) §1.22: `PerfCount`'s defaulted `==` in the header read as uncovered; it is defined once in `syscalls.cpp`. (3) A `switch` with an arm no caller reaches is a hole; `actionability` is an if-chain.

## Decisions

1. **Seam.** `open_perf_event(PerfEventSpec)`, `control_perf_event(fd, PerfAction)` (reset, enable, disable), `read_perf_count(fd)` returning value, time enabled and time running. A counter is read whole: a short read is `EIO`. The counter is opened disabled, close-on-exec, with `PERF_FORMAT_TOTAL_TIME_*`.
2. **Counters source.** Five metrics: `counters.cycles`, `.instructions`, `.cache_misses`, `.branch_misses` (hardware) and `.context_switches` (software), scope machine. Opened for the process id (its main thread) with `inherit`, user space only: that is what an unprivileged process may count at paranoid 2, and the workers are forked after the open. Rejected: system-wide per CPU (needs paranoid ≤ 0 or CAP_PERFMON, N descriptors per event); pid 0 (the sampler thread, not the thread that forks workers). Multiplexed counts are scaled by enabled/running in 128-bit arithmetic (unsigned, spelled as a GCC extension) and clamped; a counter that never ran is unreadable, not zero.
3. **errno table of `perf_event_open`.** `EACCES`, `EPERM` denied; `ENOENT`, `ENODEV`, `EOPNOTSUPP`, `ENOSYS`, `EINVAL` absent (the machine does not offer it); the rest of the man page's sixteen (`E2BIG`, `EBADF`, `EBUSY`, `EFAULT`, `EINTR`, `EMFILE`, `ENOSPC`, `EOVERFLOW`, `ESRCH`) and anything undocumented are unreadable: a failure of this attempt, not a fact about the machine. `EINVAL` as absent is a judgement: it is what an unsupported attribute returns, and what the power PMU returned for the bits it refuses; the cost of being wrong is advice-free "unsupported" for a counter we asked for badly.
4. **perf_event_paranoid is a state.** The level is read, named in the detail of a denial, and chooses the remedy: above 2 the advice is to lower it; at 2 or below it is *not* (the sysctl is not what refuses; a seccomp profile or a security module is), because advising a change that cannot work is worse than saying nothing.
5. **Power: two providers, one remedy each.** Powercap (`energy_uj`, modulus `max_energy_range_uj`, remedy: privilege or read access, never CAP_PERFMON) is tried first; a package it cannot serve is tried through the power PMU's `energy-pkg` (system-wide on the cpumask's CPU for that package; remedy: CAP_PERFMON or a lower paranoid level; counts converted to microjoules by the PMU's own scale, no modulus). When both fail they are one status: the kind is the most actionable (denied, malformed, unreadable, absent), the detail names both, the remedy is each *actionable* provider's own, labelled; a provider that merely lacks the interface contributes none. A power PMU that is not there at all is not reported as a failed provider. Packages are numbered in the order powercap lists zones named `package…`, or in the order of the PMU's cpumask without powercap.
6. **EDAC.** `edac.corrected` and `edac.uncorrected` per controller (scope memory controller, index N), found by number from mc0 to the first without a `ce_count`. Counters with modulus 2^32: the kernel keeps them as 32-bit unsigned, so a larger value is refused as malformed. None at all is one `kAbsent` status per metric at machine scope whose remedy advises nothing (F3's table); a test asserts no word of privilege in it.
7. **Ledger.** Classes P1, P2, P3, P7 for all three; the brief's table omitted P3 (the 2^32 boundary, the scale and range bounds, the multiplexing arithmetic). P7 for each is the six states, built per test (`LOADFORGE P7 FIXTURE BUILDER`) over committed trees where a tree can hold the state.
8. **Failures are filled in place** (see the coverage traps above) and `PowerChannel` is a public struct of `power.hpp` so the probe can be free functions under the complexity threshold.
9. **No ADR proposed.** Nothing here meets ADR 0001's test: each decision is local to a module.
10. **Seam additions are not pure.** `open_perf_event`, `control_perf_event` and `read_perf_count` were first pure, which made every other component's test fake of `Syscalls` abstract once merged with main, and ADR 0003 forbids this stream from editing those fakes. They now have ENOSYS defaults in `syscalls.cpp`, covered by `tests/unit/platform/syscalls_defaults_test.cpp`; `RealSyscalls`, `FakeSyscalls` and this stream's `MemFs` override them. The rule is written at the head of `Syscalls`: a call added after M1 has an ENOSYS default so that adding it breaks no implementation. ENOSYS above the seam already means "the kernel has no perf events".

## Contract questions

1. `telemetry_contract.hpp` registers both `SourceContract` and `TimelineContract`; a binary that instantiates only the first fails. Each of my test files declares `GTEST_ALLOW_UNINSTANTIATED_PARAMETERIZED_TEST(TimelineContract)`, and instantiates the suite in namespace `loadforge::contracts`, where the macro looks for it.
2. `source.hpp`: "a metric that comes back after vanishing is read again." A counter whose descriptor is dead (a CPU offlined) does not come back; the source keeps reading the descriptor and reports whatever the kernel answers. Reopening on a vanished counter is not done.
3. `sample.hpp` calls the counter unit for energy "microjoules"; the metric's unit is `kJoules` and the raw value is in microjoules, as the header's comment says. Downstream must scale by 1e-6.
4. `Unavailable.path` is a file for sysfs failures and "perf event type T config C" for perf ones; the header does not say a non-path is allowed. Chosen: it is the best name for what failed.
5. The Source interface has no way to list a directory, so controllers and zones are found by number; a hole in the numbering ends the list. The kernel numbers both contiguously as they register.
6. IMPLEMENTATION §3 names `platform/perf_events` and `platform/edac`; this brief puts them under `telemetry/sources/`. The ledger follows the brief.
7. The brief's attribution reminders offered a commit trailer other than Signed-off-by; the repository forbids it, and none is used.

## Open

- **No real EDAC or powercap capture.** F21 asks for fixtures from the real kernel. Only the power PMU description and the two "absent" trees are captures; the `two-controllers`, `intel-two-packages` and `perf-*-package` trees are modelled on Documentation/ABI/testing/sysfs-devices-edac, Documentation/power/powercap/powercap.rst and arch/x86/events/rapl.c, and say so in their README. The 32-bit width of EDAC counts is from the kernel source as remembered, not verified on hardware. A hardware run (T11) should replace them.
- **TSan could not be run locally** (the Clang 18 runtime is not installable here). The code is single-threaded; CI runs it.
- The static, scalar-only and ARM64 builds were not run locally; nothing here is architecture-specific (the 128-bit product is unsigned).
